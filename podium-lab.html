    How a race weekend is predicted

    • Before the weekend: form only, with no grid. Recent finishes, podium rate, team form and points this season.
    • After each practice: best laps give a projected grid, weighted towards later sessions. Practice is noisy (fuel loads, test programmes), so it's blended with the form-only view: 35% after FP1, 50% after FP2, 60% after FP3.
    • After qualifying: the real grid, with confirmed grid penalties applied. This is the final prediction.
    • The page checks for new data about 75 minutes after each session ends, and scores the prediction once the race result is published.

    How it keeps improving

    • Every new race result is added to the data and the model is retrained.
    • Each time, the feature search re-tests every engineered feature. It chooses using older races and reports the score on the most recent 16, so an improvement has to show up on races it didn't choose from.
    • The fixes from the original notebook still apply: races in calendar order, no future data in any feature, and rebrands (AlphaTauri → RB → Racing Bulls, Alfa Romeo → Sauber → Audi) tracked as one team.
    Data: lk-nyoka/F1-Race-Predictions and the FastF1 API. News sources are linked on each card. This is a statistical model: rain, safety cars and retirements aren't in the data, so no prediction here is a sure thing.
